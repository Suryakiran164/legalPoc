1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
PoC web app for reviewing pre-packaged commodity labels against
Legal Metrology (Packaged Commodities) Rules, 2011 (India) Rule 6 subset
(LMPC-001..009). It NEVER declares "non-compliant"/"illegal" — only
AI Observations (ok / possible_issue / missing_mandatory_declaration /
requires_human_verification) that a human inspector reviews, corrects,
and signs off on. Original design from 01_PROJECT_OVERVIEW.txt upgraded
to Gemini-first multimodal pipeline while preserving EasyOCR fallback,
deterministic rule engine, and human-review workflow.

Users: Legal Metrology inspectors, manufacturer/importer QA, auditors.
Output per scan: structured declarations, rule-by-rule observations,
3-section PDF, searchable audit record.

6. RULES (Rule 6, 2011) - 9 LMPC
--------------------------------------------------------------------------------
LMPC-001 Name & address manufacturer/packer/importer - Rule 6(1)(a) - high - checks: manufacturer_field_present, manufacturer_address_present
LMPC-002 Country of origin (imported only) - Rule 6(1)(aa) - high - country_of_origin_present (skip if not imported)
LMPC-003 Common/generic commodity name - Rule 6(1)(b) - high - commodity_name_present
LMPC-004 Net quantity + unit - Rule 6(1)(c),12,13 - high - net_quantity_present, net_quantity_has_valid_unit
LMPC-005 Month & year mfg/packing - Rule 6(1)(d) - high - mfg_date_present, mfg_date_not_future
LMPC-006 Best before/use by - Rule 6 (perishables) - medium-high - best_before_after_mfg
LMPC-007 MRP inclusive taxes - Rule 6(1)(e) - high - mrp_field_present, mrp_has_currency_indicator, mrp_is_numeric, mentions_inclusive_of_all_taxes
LMPC-008 Consumer care - Rule 6(2) - high - consumer_care_name_present, consumer_care_contact_present
LMPC-009 Unit sale price - Rule 6(11) Oct 2022 - high - unit_sale_price_present
Practical: MRP currency, net unit, future date, best-before ordering, low OCR confidence (<0.55) → requires_human_verification.
Vocabulary fixed: AI Observation, Possible Issue, Missing Mandatory Declaration, Requires Human Verification (never non-compliant/violation/illegal).

7. GEMINI INTEGRATION
--------------------------------------------------------------------------------

Env: GEMINI_API_KEY (server-only), GEMINI_MODEL=gemini-3.5-flash, GEMINI_TIMEOUT_MS=20000, GEMINI_MAX_RETRIES=2, GEMINI_CONFIDENCE_THRESHOLD=0.6

Output JSON schema per spec §4 (engine, status, language_detected, product{name,category}, declarations{manufacturer,packer,importer,country_of_origin,net_quantity,mrp,manufacture_or_packing_date,best_before_or_use_by,consumer_care,unit_sale_price}, evidence[field,raw_text,confidence,bounding_box,image_id], warnings, uncertain_regions) - never hallucinate missing fields → null/status not_found.
Parsing: strip markdown fences, extract first JSON object, coerce confidence 0-100→0-1, validate status values.
Normalization: geminiToNormalized() → declarationsToFlatFields() → flat fields for ruleEngine (manufacturer_name etc.) + field_confidences/field_statuses, overall confidence avg.
Never legal decision: extracts evidence only.

8. OCR FALLBACK & SMART FALLBACK
--------------------------------------------------------------------------------
Fallback service: ocr-service/app.py:49 /ocr (detail=1, blocks[text,confidence,bbox], full_text, avg_confidence). EasyOCR en only (hi could be added via Reader(['en','hi'])).
Pipeline steps backend/src/services/ocrPipeline.js:1:
1 Upload → 2 Preprocess → 3 Call Gemini → 4 Validate → 5 If success + score >=0.6 → use Gemini → 6 If fails (timeout, API error, invalid JSON, quota, unsupported image, low confidence, missing mandatory, almost no text, malformed, limits) → EasyOCR → 7 Normalize both → same extraction→rules.
Reliability: geminiScore = textCoverage*fieldCoverage*confidence*schemaValidity*warningsPenalty; textCoverage min(1, rawLen/80+evidence*0.05), fieldCoverage found/6 mandatory. Decision shouldFallback() checks low confidence (<0.35), score<threshold, no evidence, no text, 2+ mandatory missing, invalid schema.
Dual verification (ENABLE_DUAL_OCR=true): run both, compareNormalized() for mrp/net qty/country/mfg/best_before; if disagree → conflicts[] with resolution human_review_required, final status conflicting→requires_human_verification; if fallback more reliable (+0.15) prefer fallback.

9. IMAGE PREPROCESSING
--------------------------------------------------------------------------------
backend/src/services/imagePreprocessor.js:1 via sharp (or passthrough if missing):

10. MULTI-IMAGE & MULTILINGUAL
--------------------------------------------------------------------------------
Multi-image: POST /api/scans accepts field image (single) or images (array 8) via multer.fields backend/src/middleware/upload.js:1; pipeline handles all images together (Gemini) or per-image EasyOCR then mergeMultiImageResults(); conflicting net qty/MRP across images → field_status conflicting, warnings CONFLICTING_DECLARATION, observations downgraded to requires_human_verification. images[] stored with image_id, url, storage_path, mimetype.
Multilingual: Gemini language_detected via prompt (en,hi,kn,ta,te,ml,mr,bn,gu,pa); raw_text preserves original script (e.g. "अधिकतम खुदरा मूल्य ₹99"), normalized value 99 stored + confidence. EasyOCR fallback detects Devanagari [\u0900-\u097F]→hi, Kannada→kn, Tamil→ta, Telugu→te, Malayalam→ml and sets language_detected accordingly. Field extraction regex handles ₹/Rs/INR variants, Indian formatting 1,00,000.

11. CONFIDENCE & EVIDENCE & EDGE CASES
--------------------------------------------------------------------------------
Confidence: per-field 0..1 (geminiService, normalizedOcr). Critical fields <0.55 → ruleEngine downgrades ok → requires_human_verification. Overall confidence avg of verified fields.
Evidence: per extracted field {field, raw_text, confidence, bounding_box{x,y,width,height}, image_id, engine} stored in normalized_ocr.evidence and scans.evidence; UI scan detail shows click-to-region (bbox) and image_id. Also blocks, uncertain_regions.
Distinction: status verified / not_found / unreadable / not_applicable / conflicting / requires_human_verification (not confused).
Edge cases handled per spec §13: missing/unreadable/multiple/different MRPs, malformed net qty, kg/g/L/ml decimals, Indian number formatting, partial/cropped/glare/blur/low-res/rotated/curved/wrinkled/sticker-over-sticker/duplicate, future mfg, best-before ordering, missing manufacturer/importer/consumer care, imported ambiguity, stylized fonts, small text, barcode/QR, promotional vs MRP, hallucination, timeout/rate limit/malformed JSON/unavailable, fallback failure, engine disagreement — all → appropriate status/warning, never false compliance.

13. API
--------------------------------------------------------------------------------
Auth: JWT Bearer via api/client.ts interceptor (lm_token). All /api/* requireAuth except /auth.

POST /api/auth/register {email,password,name,role} → {token,user}
POST /api/auth/login → {token,user}

POST /api/scans (multipart: image single or images 1-8) — pipeline: preprocess→Gemini→fallback→normalize→ruleEngine → persist. Returns:
{
 success:true, scan_id, ocr:{primary_engine,fallback_used,confidence,status,warnings,conflicts,language_detected,attempts},
 analysis:{fields,observations,requires_human_verification,evidence},
 id, image_url, images, observations, summary, ocr_engine etc.
}
Rate limit 15/min per user, 10MB/file, JPEG/PNG/WEBP.

POST /api/scans/:id/analyze — re-run pipeline on stored images (downloads from Storage), updates scan.

GET /api/scans?q=&status=&limit=100 — in-memory filter over recent 100, now also searches ocr_engine/language_detected.

GET /api/scans/:id — single scan.

PATCH /api/scans/:id/fields {fields:{...}} — human correction, re-runs ruleEngine, appends correction_history, status corrected.

POST /api/scans/:id/review {decision,notes} — human review, status reviewed.

GET /api/scans/:id/report.pdf — streams PDF; now requires Bearer token via api.get blob (frontend ScanDetail downloadPdf()), not direct <a href>.

GET /api/rules, PUT /api/rules/:ruleId (admin) — live rule edit without redeploy.

GET /api/dashboard/summary — aggregates scans, possible_issues, requires_verification.

Errors: never raw Gemini errors; maps to user messages:
timeout → "Primary AI extraction timed out. Fallback OCR was used."
quota 429 → "quota exceeded. Fallback OCR was used."
invalid JSON → "invalid data. Fallback OCR was used."
unavailable → "currently unavailable. Fallback OCR was used."
both failed → "OCR could not reliably process this image. Please upload a clearer image."

20. SUCCESS CRITERIA
--------------------------------------------------------------------------------
Upload → Gemini (if confident) → normalized → ruleEngine → observations → human review
       ↘ if fails/low reliability → EasyOCR → normalized → ruleEngine → human review
       → if disagree → conflict → Requires Human Verification
       → if both fail → "Unable to reliably extract... upload clearer image" (no false compliance)
Feels like natural evolution, not toy demo; no hard-coded AI results; EasyOCR retained; legal decisions never in LLM; robust Gemini-first → fallback → normalized → deterministic rule engine → human review pipeline on top of existing codebase.
